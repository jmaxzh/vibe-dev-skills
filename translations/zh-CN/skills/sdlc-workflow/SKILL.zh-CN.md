# SDLC Workflow

## 工作流程与能力

意图 → 需求 → 技术方案 → 实施。

- 启用本技能后，根据用户目标确定需要完成的阶段，按“需求 → 技术方案 → 实施”的依赖顺序，在本次任务范围内补齐缺失或失效的前置成果，无需用户逐阶段调用。
- 复用上下文和现有材料中仍适用的需求、方案及决策；以内容是否足以支撑后续阶段为准，不因缺少独立文档而重复执行。
- 前置条件满足后，连续推进至用户要求的阶段，不逐阶段请求确认，也不自动扩展至后续阶段。关键歧义按对应阶段的澄清规则处理，重大取舍按“交付质量”的确认要求处理，仅暂停受影响的工作。

按实际执行阶段读取并遵循对应文件：

- 意图 → 需求：[需求](references/intent-to-requirements.md)
- 技术方案：[技术方案](references/requirements-to-technical-design.md)
- 实施：[实施要求](references/implementation.md)

独立可选能力仅按用户明确要求执行；禁止因进入主流程阶段自动触发：

- 项目初始化：[项目初始化](references/project-initialization.md)。先明确项目目标与范围并建立知识库，再建立最小可验证工程骨架。
- 知识库审查：[知识库审查](references/project-knowledge-base-review.md)。禁止因日常知识库读取或更新自动启动。

## 通用规则

### 适用范围

- 以下通用规则约束执行本技能时的对话回答与交付产物；交付产物指代码、文档等可交付成果，不含普通对话回答。各节按其声明的对象适用。

### 回答中的术语与表述

- 本节及“解释与沟通”仅约束对话回答；文档产物遵循按需读取规则中的“指令与文档设计原则”。

- 优先沿用项目或文档已定义的术语；未定义时，采用业界通用术语。首次使用可能影响读者理解的术语时，按需解释其含义。
- 同一概念使用同一规范术语，同一术语仅表达一个概念；不要为避免重复轮换同义词。
- 识别原始表述的实际含义，转换为规范表述；避免机械沿用。
- 存在术语多义、边界不清或定义冲突时，明确含义、适用范围及与相近术语的区别。
- 明确必要的执行主体、操作对象、前置条件、约束及预期结果；消除指代歧义。
- 保持事实准确、逻辑清晰、语义完整；删除套话、重复及无效修饰，保留必要的背景、因果、权衡与不确定性。
- 按内容的逻辑顺序表达；明确否定范围，区分可能原因与确定原因。
- 保留已经清晰、准确且符合要求的内容；仅在需要纠错、补充、消除歧义或适配要求时改写；避免过度简化。

### 解释与沟通

- 从读者已知出发，交代理解内容所必需的背景、问题缘由和关键概念；不预设读者掌握超出其合理知识背景、且理解当前内容所必需的知识。
- 解释过程或机制时，按因果关系逐步展开，补齐必要的逻辑环节，讲清原因、过程与结果；按理解难度使用通俗语言和具体例子，详略适度。

### 交付质量

- 以最终交付的正确性、完整性和可维护性为标准，优先直接采用合理方案。
- 修改已有交付产物时，增量修改，保留有效结构与信息。
- 修改代码、配置等非文档产物时，在任务范围内纠正错误，替换失效、冲突或被新内容取代的部分，删除重复或无关内容；文档内容修改遵循按需读取规则中的“指令与文档设计原则”。
- 授权范围内、实现目标所必需的组织及职责调整直接推进；仅对超出授权范围、改变需求或需要用户决定的重大取舍请求确认。复用已有授权，不重复确认。
- 清除最终交付产物中由试错、误解、纠正、回退及废弃方案遗留的无效代码、文档、配置和测试；保留必要的历史记录与验证证据。

## 技能依赖

- 文档产物任务需要已安装的 `sdlc-instr-doc-design` 技能。通过运行环境的技能目录发现，并使用可用的技能机制加载，采用实际注册名称及命名空间。没有技能加载器时，从发现的安装位置读取入口和相关资料；不预设检出路径、用户目录或命名空间。
- 无法加载必需技能或资料时，明确缺项，仅暂停依赖其规则的工作，继续独立部分。不宣称已应用规则、不静默跳过，也不自动下载或安装依赖。
- 说明完整插件已包含此依赖。skills CLI 的最小安装组合为 `npx skills add jmaxzh/vibe-dev-skills --skill sdlc-workflow --skill sdlc-instr-doc-design`；该命令仅为安装说明，不构成未经授权执行的要求。
- UI、MySQL 和 CC Connect 技能保留各自适用范围与启用规则；安装整套技能不等于每项任务都启用全部技能。

## 按需读取规则

- 设计、编写、修改或审查文档产物时，按[技能依赖](#技能依赖)发现并遵循已安装的 `sdlc-instr-doc-design` 技能。
- 回答中包含操作或排障说明时，按[技能依赖](#技能依赖)定位已安装的 `sdlc-instr-doc-design` 资料，仅按需读取其 `references/document-design.md` 的操作说明或故障排查说明章节，不启用其主流程或整套文档设计规则。
- 全流程按需读取用户指定的项目知识库；项目初始化时按初始化规则确定知识库位置，其他场景需要读取但位置未明确时，请求指定。
- 使用项目知识库时，读取[项目知识库规范](references/project-knowledge-base.md)，按实际活动遵循对应条款；变更受保护文档前，遵循具体修改确认要求。
